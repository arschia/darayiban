# دستیار مالی دارایی‌بان

دستیار داخل همان رابط وب/PWA و کد مشترک Android قرار دارد. درخواست‌ها به Supabase Edge Function می‌روند تا کلید مدل در مرورگر یا APK قرار نگیرد. مدل پیش‌فرض `google/gemini-3.5-flash-lite` از Vercel AI Gateway است و با `AI_MODEL` قابل تغییر است.

## امکانات

- خواندن تراکنش‌ها، دارایی‌ها، موجودی بانک‌ها، حساب‌ها، بودجه‌ها، بدهی و طلب، هدف ترکیب دارایی و تنظیمات اعلان همان کاربر.
- محاسبه مجموع هزینه و درآمد در دیتابیس، بدون محدودیت ۲۵۰ ردیفی داشبورد. خواندن جزئیات صفحه‌بندی دارد و به ۵۰ رکورد در هر فراخوانی محدود است.
- برچسب‌گذاری گروهی و ویرایش توضیح، دسته، مبلغ و زمان تراکنش، همچنین ویرایش دارایی، بودجه، بدهی، موجودی بانک و هدف ترکیب دارایی. هر فراخوانی تا ۲۵ رکورد را به‌صورت یک تراکنش دیتابیس تغییر می‌دهد.
- ساخت بودجه و هشدار سقف هزینه از روی درخواست صریح کاربر. موارد مبهم باید با سؤال روشن شوند؛ مدل نباید کاربرد خرید نامشخص را حدس بزند.
- گزارش هر تغییر و بازگردانی آن با کنترل تعارض؛ تغییر جدیدتر کاربر در همان فیلد بازنویسی نمی‌شود.
- گفتگوهای ذخیره‌شده و قابل بازکردن با `/?assistant=<conversation-id>`، با RLS و بررسی مالکیت.

## فعال‌سازی

۱. در [Vercel AI Gateway](https://vercel.com/docs/ai-gateway/authentication-and-byok/api-keys) یک API key ایجاد کنید. اعتبار مصرف مدل جدا از اشتراک ChatGPT است. مقدار کلید را در GitHub، کد frontend، پیام گفتگو یا متغیرهای `NEXT_PUBLIC_*` نگذارید.

۲. کلید را در Supabase پروژه SelfMali، بخش Edge Functions → Secrets با نام `AI_GATEWAY_API_KEY` ذخیره کنید. متغیرهای اختیاری:

| نام | کاربرد |
|---|---|
| `AI_MODEL` | شناسه مدل در Gateway؛ پیش‌فرض `google/gemini-3.5-flash-lite` |
| `AI_INPUT_USD_PER_MILLION` | نرخ ورودی برای برآورد هزینه، در صورت تغییر مدل |
| `AI_OUTPUT_USD_PER_MILLION` | نرخ خروجی برای برآورد هزینه، در صورت تغییر مدل |

برآورد پیش‌فرض بر اساس فهرست مدل Gateway در ۵ سپتامبر ۲۰۲۶، ۰٫۳۰ دلار ورودی و ۲٫۵۰ دلار خروجی در هر میلیون توکن است. تخفیف کش و تفاوت مسیر ارائه‌دهنده در این برآورد لحاظ نمی‌شود. برای مدل دیگر بدون نرخ تنظیم‌شده، هزینه نامعلوم ثبت می‌شود؛ صورتحساب واقعی مرجع نهایی است.

۳. migration `20260905125343_financial_assistant.sql` را فقط یک‌بار اعمال کنید. این تغییر داده‌های مالی موجود را ویرایش نمی‌کند. به `pg_cron`، `pg_net`، `get_push_config()` و تنظیمات Vault موجود پروژه برای Web Push تکیه دارد. فایل migration قبلی موجودی دستی باید روی محیط تازه نیز اجرا شده باشد.

۴. Edge Function با نام `financial-assistant` و entrypoint `index.ts` از پوشه هم‌نام را با `verify_jwt=true` منتشر کنید. فایل‌های `core.ts` و `tools.ts` نیز لازم‌اند. تابع حتی بعد از تأیید پلتفرم، کاربر را با `auth.getUser` بررسی می‌کند و ابزارهای مالی فقط با JWT همان کاربر و RLS اجرا می‌شوند. service role فقط برای ثبت تاریخچه و محدودیت درخواست در دسترس handler است و به مدل یا ابزارهای مالی داده نمی‌شود.

۵. تابع `assistant-spending-alerts` همراه `../_shared/push.ts` را با `verify_jwt=false` منتشر کنید. این تابع فقط `POST` با `x-cron-secret` معتبر موجود در Vault می‌پذیرد. مقدار secret نباید در مخزن ذخیره شود. migration یک Cron هر دقیقه برای همین تابع ایجاد می‌کند. اگر انتشارها جداگانه انجام می‌شوند، تابع زمان‌بندی را قبل از migration منتشر کنید و پس از migration سلامت اولین اجرا را بررسی کنید.

۶. نسخه frontend را پس از تکمیل backend منتشر کنید. نبود API key با حالت غیرفعال و پیام مشخص نمایش داده می‌شود. برای ورود منوی جدید به اپ نصب‌شده Android باید APK تازه ساخته و نصب شود؛ APK قبلی خودبه‌خود تغییر نمی‌کند.

## هشدارها

هشدار امروز فقط تا پایان همان روز به وقت تهران فعال است. هشدار هر روز، مجموع روز جاری را از ابتدا محاسبه می‌کند و می‌تواند فیلتر تگ یا دسته داشته باشد. شرط «بیشتر از» به‌صورت `>` اجرا می‌شود. تراکنش‌های حذف‌شده، آینده و ارزهای غیر از IRR/IRT شمرده نمی‌شوند. جمع از دیتابیس است و تراکنش دستی و پیامکی را پوشش می‌دهد.

هشدار در هر روز و برای هر قاعده یک شناسه یکتا دارد. ارسال ناموفق تا ۸ تلاش و با فاصله حداقل ۵ دقیقه تکرار می‌شود. ممکن است سرویس Push تحویل را بپذیرد اما دستگاه اعلان را نمایش ندهد؛ نمایش قطعی دستگاه قابل تضمین نیست. در حالت نادر قطع ارتباط بعد از پذیرش Push و قبل از ثبت نتیجه، تکرار تحویل ممکن است رخ دهد و `tag` اعلان یکسان باقی می‌ماند.

Push به قابلیت موجود وب/PWA وابسته است و کاربر باید مجوز اعلان دستگاه را فعال کند. iOS باید از PWA نصب‌شده روی Home Screen استفاده کند. WebView اپ Capacitor فعلی Web Push بومی ندارد؛ این تغییر FCM یا اعلان پس‌زمینه بومی Android اضافه نمی‌کند. گزارش اعلان در حساب ذخیره می‌شود و می‌توان Push را از PWA همان حساب دریافت کرد. پیامک یا هزینه‌ای که وارد دارایی‌بان نشده قابل رصد نیست.

## محدودیت مصرف و حریم خصوصی

هر کاربر یک درخواست فعال، حداکثر ۸ درخواست در دقیقه و ۶۰ درخواست در ۲۴ ساعت دارد. هر پاسخ تا ۸ مرحله مدل، ۲۴۰۰ توکن خروجی در هر مرحله و مهلت ۸۵ ثانیه دارد. گفتگو تا ۱۰۰ درخواست نگهداری می‌کند؛ ۱۲ درخواست آخر به مدل داده می‌شود. برای ادامه موضوع قدیمی باید اطلاعات لازم دوباره با ابزار خوانده یا از کاربر پرسیده شود.

فقط داده مالی مورد نیاز و متن گفتگو به ارائه‌دهنده مدل فرستاده می‌شود. ابزارها شماره کامل کارت/حساب، توکن اتوماسیون، کلیدهای Push و کلیدهای محرمانه را نمی‌خوانند. یادداشت‌های متنی غیرقابل‌اعتمادند. دستیار ابزار پرداخت، انتقال بانکی، معامله واقعی، اجرای SQL آزاد یا حذف دائمی ندارد. ارزش دارایی بر مبنای مقدار ثبت‌شده است و قیمت زنده بازار محسوب نمی‌شود.

## آزمون

`npm run test:assistant` تست‌های واقعی PostgreSQL داخل PGlite، مرزبندی حساب‌ها، جمع بیش از هزار تراکنش، ریال/تومان، ویرایش اتمیک، بازگردانی، درخواست تکراری، هشدار امروز، مرز نیمه‌شب تهران، احراز هویت endpoint و اجرای ابزار با مدل آزمایشی را اجرا می‌کند. برای اجرای همین تست‌های Edge در Node فقط importهای `npm:` و سطح env/test مربوط به Deno تطبیق داده می‌شوند. کد ابزار، احراز هویت و handler جایگزین نمی‌شود. تست مدل آزمایشی جای آزمون ارائه‌دهنده واقعی را نمی‌گیرد.

پس از ثبت کلید، با حساب تست یک سؤال تحلیلی، برچسب‌گذاری یک تراکنش، بازگردانی و هشدار هزینه با Push فعال را در محیط منتشرشده بررسی کنید. تا قبل از این مرحله، پاسخ واقعی مدل و تحویل اعلان روی دستگاه تأییدشده نیستند.
